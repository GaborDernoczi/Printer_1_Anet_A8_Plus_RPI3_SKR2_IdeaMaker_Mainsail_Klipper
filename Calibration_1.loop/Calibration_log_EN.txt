2. DIAGNOSIS - X AXIS ERROR (SOLVED)
-------------------------------------------------------------------------------

First assumption (it was WRONG):
  The -2.74 % X error is mechanical (loose belt, slipping pulley).

Correction, after it turned out that X rot.dist was 40.9 during the test:

  Formula:  measured = 50 x RD_actual / RD_configured

  X:  48.63 = 50 x RD / 40.9  ->  RD_actual = 39.78
  Y:  49.76 = 50 x RD / 40.0  ->  RD_actual = 39.81

  The two axes are practically identical -> THERE IS NO mechanical fault.
  The whole deviation was caused by the incorrectly entered 40.9.

SOLUTION: X rotation_distance = 40 (theoretical value for a 16-tooth GT2
          pulley)
STATUS:   DONE - confirmed by test #2 (prediction 49.73 / actual 49.74)

4. DIAGNOSIS - Z AXIS (IN PROGRESS)
-------------------------------------------------------------------------------

IMPORTANT PRINCIPLE:
  The Z error does NOT come from stepper_z rotation_distance!
  Because of the TR8x8 lead screw, rotation_distance = 8 is mathematically
  exact, and it must NEVER be modified.

  From the second layer on, every layer is accurate. ALL height error is
  created in the FIRST LAYER: if the nozzle is too high, the first layer
  is thicker than nominal, and this is added as a constant error to the
  whole model.

  -> The solution is always the [bltouch] z_offset.

SIGN RULE IN KLIPPER:
  LARGER z_offset = the nozzle is CLOSER to the bed = MORE squish
                  = the printed part will be SHORTER

CALCULATION:
  Test #1: 50.21 mm with z_offset 1.15 -> +0.21 correction would be needed
  Test #2: 50.17 mm with z_offset 1.15 -> +0.17 correction would be needed
  Ideal value is therefore: 1.15 + 0.17 = 1.32

APPLIED STEP:
  z_offset 1.15 -> 1.25 (only +0.10, a cautious approach to protect the bed)
  Expected #3 result: Z ~50.07 mm
  ACTUAL #3 result: 50.06 mm -> the prediction was correct

POSSIBLE FURTHER FINE-TUNING (optional):
  For the remaining +0.06 mm, z_offset 1.25 -> 1.31 would be needed.
  BUT: 0.06 mm is already within the error margin of the caliper and the
  surface roughness, and more squish can cause elephant foot.
  RECOMMENDATION: LEAVE IT AT 1.25.

STATUS: DONE (within acceptable error margin)

5. Z-OFFSET CALIBRATION - STEP BY STEP (REFERENCE)
-------------------------------------------------------------------------------

PREPARATION
  - Bed heated to operating temperature (e.g. 60 C for PLA)
  - Nozzle at ~150 C (important because of thermal expansion!)
  - Nozzle must be clean
  - Sheet of paper ready (~0.1 mm)

STEPS (Mainsail console)
  1.  G28
  2.  PROBE_CALIBRATE
      -> the BLTouch probes, the head moves aside and lowers
      -> the "Z Offset Calibration" panel appears with + / - buttons
  3.  TESTZ Z=-0.17          (or on the panel: -0.05 x3 and -0.02 x1)
  4.  Paper test:
        Good:       it slides, but you can feel it scratching
        Too loose:  TESTZ Z=-0.02
        Too tight:  TESTZ Z=+0.02
  5.  ACCEPT
      -> the console prints: "bltouch: z_offset: 1.320"
  6.  SAVE_CONFIG
      NOTE: this RESTARTS Klipper, that is normal!
  7.  Verification: the SAVE_CONFIG block should contain
        #*# [bltouch]
        #*# z_offset = 1.320
  8.  Redo the bed mesh (the Z reference has changed):
        G28
        BED_MESH_CALIBRATE
        SAVE_CONFIG
  9.  Reprint the test cube

BAILING OUT: the ABORT command at any time, without saving

WARNING:
  Once SAVE_CONFIG has run, the z_offset value at the TOP of the file becomes
  ineffective - the SAVE_CONFIG block always overrides it. Do not be surprised
  that the old number stays there.

  If you want to edit the top of the file MANUALLY: first DELETE the
  "#*# [bltouch]" and "#*# z_offset = ..." lines from the SAVE_CONFIG block,
  then run FIRMWARE_RESTART.

6. SYMPTOM: MAINSAIL DISPLAYED -4.85
-------------------------------------------------------------------------------

CASE: While adjusting the Z offset, Mainsail showed a value of -4.85.
      The user (correctly) did not start the movement.

EXPLANATION:
  What was shown is NOT the offset, but the CURRENT Z POSITION OF THE HEAD.
  This appears when you look at the dashboard "Z offset" live adjust field
  instead of the dedicated PROBE_CALIBRATE panel.
  The two are SEPARATE things.

RULE: if you see a Z below -4 before a movement, always stop.

7. CORNER OOZING ("EDGE PROBLEM") - IN PROGRESS
-------------------------------------------------------------------------------

CAUSE:
  - Pressure Advance was not configured either in IdeaMaker or in Klipper
  - Acceleration and Jerk are disabled in the slicer (this is good, Klipper
    handles them), but Klipper's 3000 mm/s^2 acceleration is too much for
    the acrylic frame

APPLIED SETTINGS (printer.cfg):
  [extruder]
    pressure_advance: 0.05
    pressure_advance_smooth_time: 0.040
  [printer]
    max_accel: 1500              (instead of 3000)
    square_corner_velocity: 5.0

NEXT STEP - PA CALIBRATION based on the evaluation of print #3:
  - If improved but still faulty  -> go towards 0.07 ... 0.10
  - If nothing changed            -> probably a BOWDEN setup -> 0.4 ... 0.8
  - If the corners now pull in (under-extrusion in turns) -> back to 0.03
  - If the corners still ooze after PA -> square_corner_velocity 5.0 -> 3.0

Official guide: https://www.klipper3d.org/Pressure_Advance.html

    Original (Klipper stock example value, never calibrated):
      pid_Kp = 22.2    pid_Ki = 1.08    pid_Kd = 114

    PID_CALIBRATE HEATER=extruder TARGET=<printing temperature>
    SAVE_CONFIG

    Measured values:
      pid_Kp = 39.518  pid_Ki = 3.421   pid_Kd = 114.109

    DEVIATION:
      Kp: +78 %
      Ki: +217 %   <-- THIS IS THE KEY ONE
      Kd: ~0 %

    EVALUATION:
    Ki was set more than three times lower than required. The integral term
    is responsible for eliminating steady-state error; if it is too small,
    the heater follows the target sluggishly and with overshoots -> slow
    temperature oscillation -> fluctuating viscosity -> WAVY, UNEVEN WALL.
    This explains the moire-like pattern seen on the right-hand face in the
    "test #3" photo.

    IN THE RUNNING CFG: the values are in the [extruder] section of the
    SAVE_CONFIG block, and the control/pid_K* lines at the top of the file
    are commented out. This is the CORRECT state - do not uncomment them,
    because the SAVE_CONFIG block would override them anyway.

    STATUS: DONE

(B) [heater_fan fan2] (PB5)
    No "heater:" is specified, so by default it is tied to the extruder.
    If this is actually a mainboard cooling fan, it should be a
    [temperature_fan] instead, otherwise it only spins when the hotend is hot.

(C) LEFTOVER IN THE SAVE_CONFIG BLOCK
      #*# [stepper_z]
      #*# position_endstop = 0.300
    Leftover from when there was still a physical Z endstop. Since
    "probe:z_virtual_endstop" is used now, Klipper ignores it.
    It causes no error, but it can be deleted after the next SAVE_CONFIG.

(D) NO INPUT SHAPER
    It would be worth configuring against ringing / ghosting, based on an
    accelerometer or a ringing test tower.

11. EXTRUDER CALIBRATION (E-STEP) -- DONE 2026-09-13
-------------------------------------------------------------------------------

This is the "real root cause" behind the flow / dimension / corner issues.

MEASUREMENT:
  Mark:              120 mm at the extruder inlet
  Command:           G1 E100 F60
  Remaining mark:    13 mm
  Actually fed:      120 - 13 = 107 mm

CALCULATION:
  RD_new = 33.500 x (107 / 100) = 35.845

RESULT:
  rotation_distance:  33.500  ->  35.845
  The extruder was pushing 7 % MORE material than required on ALL prints
  so far.

CONSEQUENCES:
  - This directly explains the CORNER OOZING: material already piles up in
    a turn, and on top of that there was a 7 % surplus.
  - It also contributed to the wavy wall (together with the bad PID).
  - THE CUBE DIMENSIONS WILL CHANGE! Because of the reduced material the
    walls become thinner -> the outer dimension may shrink slightly.
    -> The dimensional calibration (XY Size Compensation) MUST BE
       RE-EVALUATED.

IMPORTANT: if a Flowrate < 100 % or an XY Size Compensation is set in
IdeaMaker, it is now worth RESETTING them to default, because they were
compensating for the 7 % over-extrusion. Otherwise there will now be
under-extrusion.

STEPS TO REPEAT THE PROCEDURE:
  1. Heat the hotend to printing temperature
  2. Mark 120 mm on the filament at the extruder inlet
  3. G1 E100 F60        (slowly! that is why max_extrude_only_distance was
                         needed)
  4. Measure how much of the mark is left
  5. new_value = old_value x (actual / 100)
  6. Write it into printer.cfg, then run FIRMWARE_RESTART
